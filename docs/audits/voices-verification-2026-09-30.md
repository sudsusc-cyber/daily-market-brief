## 通用修复

1. 对全大写字母缩写，仅将末尾小写 `s` 视作语法复数。继续验证缩写身份、
   数字、单位和版本标识；`AWS`、`GPT-6.1`、`Claude-3-Sonnet` 不被截断。
2. 模型状态核验按动作作用的对象识别，区分融资、会议、建设等公司事件
   与模型训练、评估、部署、服务事件；保留主被动语序、因果背景与并列对象
   检查。真正的模型状态新闻仍须满足既有范围和正文证据要求。
3. 翻译继续核对延期状态及 `until` / `unless` 限定，防止恢复时丢失条件。
4. 已选中且仅缺合格中文译文的候选，可单独重译一次并重新核验同一筛选
   结果。整个关键发言板块共享最多 2 次请求、6 条候选的恢复预算，每次
   请求超时 20 秒，并受现有 LLM 全局时间/token 截止约束。恢复不重新打分、
   不放宽来源门槛、不循环生成到“通过”。
5. 审计 manifest 保存有界、脱敏的候选原文、来源、日期、译文、筛选决定、
   核验原因及恢复前后结果；保留第一次拒绝记录。这些数据不进入邮件正文。

## 后续检查：选稿不得依赖现成中文片段

英文原文具备完整证据即可参与选稿，系统负责翻译。进一步检查发现三个
影响这条路径的缺口，已用类别级规则修复：

- 选稿 prompt 曾复用发布 prompt 的“英文不可直接刊出”要求，可能将译文
  缺失误当作新闻不值得选。现将原文价值判断与翻译/发布分开；选稿允许
  返回完整英文原句，后续发布仍核对对应原文与译文。
- 翻译器曾以“出现任意一个汉字”作为已是中文的判断。英文中的中文人名
  或媒体名因此可能导致整句跳过翻译。现统一使用发布器的中文正文判定。
- 选稿返回与原文完全一致的英文句子时，发布器优先使用原句，即使已存在
  合格译文也可能在中文排版检查中拒绝。现优先使用与该完整原句精确绑定
  且核验通过的译文，不允许借用其他句子的翻译。

关键发言诊断区分 `translation_unavailable`、`source_evidence_unavailable`
与 `publication_quality_rejected`。翻译失败单独进入内容质量状态和提示，
不再被描述成原始新闻内容未通过核验；它仍属内容降级，不触发重复发送。

新增纯英文原文选稿后恢复刊出、中英混排译入、已有中文不重复翻译、
原文与长期判断证据映射、翻译失败分类的回归。全量离线测试 2,015 项
通过，Ruff 和差异检查通过；未调用真实 LLM 或发送邮件。
