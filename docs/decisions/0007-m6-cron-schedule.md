# ADR-0007 — M6 cron 调度时间(北京周二到周六 08:00)

- 日期:2026-04-30
- 状态:**已被 M6 实施修订**(2026-05) — 主触发改为外部 cron-job.org workflow_dispatch
  (秒级精度,BJT 06:30),GH schedule 仅作兜底,且时间提前到 BJT 06:30
  (`30 22 * * 1-5` UTC)。详见 [.github/workflows/daily.yml](../../.github/workflows/daily.yml)
  顶部注释。本 ADR 保留作为历史决策依据,但 cron 时间和触发架构已不同,
  新读者请以 daily.yml 为准。
- 影响范围:M6
- 触发:用户在 M4 验收期间追加指令"邮件理应是周二到周六早上每天 8 点北京时间(因为美盘收盘)"

## 背景

PLAN 第 7 节 M6 任务 1 给出的 cron 例子是:
```
cron: 30 23 * * 0-4(周一到周五凌晨,北京时间次日 7:30)
```

这个例子翻译过来是 **UTC 周日-周四 23:30 = 北京周一-周五 07:30**——把"周一早 7:30"也包括了。

问题:
- 北京周一早收到的邮件,数据反映的"昨日"是上周五美股(周末美股不开盘)。
- 真正想反映的是"美股周一收盘后"的数据,这要到**北京周二凌晨**才齐全。
- 所以**北京周一发邮件价值很低**(冷饭),应当跳过。

## 决策

**M6 实施时的 cron**:`0 0 * * 1-5`(UTC 周一到周五 00:00 = 北京周二到周六 08:00)

| 美股交易日(美东) | 北京数据齐全时刻 | 邮件发送日(北京) |
|---|---|---|
| 周一 | 周二 04-05:00 | 周二 08:00 |
| 周二 | 周三 04-05:00 | 周三 08:00 |
| 周三 | 周四 04-05:00 | 周四 08:00 |
| 周四 | 周五 04-05:00 | 周五 08:00 |
| 周五 | 周六 04-05:00 | 周六 08:00 |
| 周六 / 周日休市 | — | 周日 / 周一**不发** |

cron 表达式:
```
on:
  schedule:
    - cron: "0 0 * * 1-5"   # UTC 周一-周五 00:00 = 北京周二-周六 08:00
```

GitHub Actions cron 注意事项:
- GH 不保证准点触发,实际可能延后 5-15 分钟,所以"早 8:00"实际邮件到达可能 8:05-8:15
- 若希望更稳准点,可把 cron 提早 10 分钟到 `50 23 * * 0-4`(UTC 周日-周四 23:50 = 北京周一-周五 07:50,即北京周二-周六 07:50)

## 节假日

PLAN 第 9 节边界情况里写的"美股节假日(如圣诞)→ 跳过当日,不发邮件",在 M6 实施时:

- 美股节假日(每年 ~10 天:元旦、马丁路德金日、总统日、耶稣受难日、阵亡将士日、6/19、独立日、劳动节、感恩节、圣诞节)→ 当日美股不交易 → **次日不发**
- 港股节假日相互错开,暂保持简单:**只看美股节假日**,因为本项目主仓是美股;港股那两只(0700.HK / 9992.HK)如果当日休市,company_news 自然 0 候选,模板降级显示
- 节假日表存哪:**M6 用一个简单的 `state/us_holidays_2026.json`**(从 NYSE 官网手抄一次;每年 11 月底刷新一次为下年表)
- 实施位置:`src/utils/holidays.py` 加 `is_us_market_open(date)`;main.py 启动时若不开盘则 `sys.exit(0)` 不发邮件

## 与 PLAN 的偏差

| PLAN 第 7 节 M6 例子 | 本 ADR 锁定 | 偏差原因 |
|---|---|---|
| `30 23 * * 0-4`(北京周一-周五 07:30) | `0 0 * * 1-5`(北京周二-周六 08:00) | PLAN 例子把周一也包含进去,但周一对应美股是上周五,数据冷;调整为周二-周六更合理 |
| 时间 07:30 | 时间 08:00 | 用户明确指定 08:00;若想准点 08:00 可微调 cron 提早 10-15 分钟 |
