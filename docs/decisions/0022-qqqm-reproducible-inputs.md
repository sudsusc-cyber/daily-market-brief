# QQQM：同输入同值与可追溯取数（v1.8）

日期：2026-09-04。仅修复取数一致性、计算重放和缓存选择；不改邮件版式、乐观情景、增长率、折现率、退出 PE 或差额收益率定义。

## 问题及证据边界

之前程序已经由 Python 计算，而非让 DeepSeek 自行输出估值，但完整直取数据仅读取一次。正式邮件日志只有结果、数据日、远期口径，没有完整输入，因此无法追溯同日源修订或取数过程中变动。另一个缺口是运行时和 workflow 缓存合并各自按日期选择，同日修订缺乏统一核验时间排序。

历史基线数据可独立重算为 331.2820647655544。此前 9 月 3 日来源包 NAV=295.446047、PE_ttm=28.61、配对=28.06/21.21、DIV=1.3053，对应 331.2919213238106；不能用它复现那次邮件的 327.6582。原发送记录没有保留下完整包，无法据此确定当时究竟哪个字段不同。本修复不臆定具体旧字段错误，也不把估值人为锁死在 331。

## 固定规则

- 估值仍为用户选择的单一乐观情景；第一年不重复乘 15%，2–5 年 15%，6–10 年 7%，退出 PE 24.65，折现率 10% 加费用 0.15%。
- 使用固定 40 位 Decimal 上下文计算，不受其他调用者的精度/舍入设置影响，不在中间步骤取整。
- 输入指纹覆盖 NAV、TTM PE、同日远期配对、TTM 分红、远期口径及固定计算参数。现价、抓取时间、日期文字、URL 顺序和传输路径不进入数值指纹。
- 同数值输入及口径/公式必须产生完全相同的估值。仅现价变化时，只更新邮件 IRR=估值/现价−1；不是长期年化收益率。
- 日期仍独立严格验证；排除日期于数值指纹不等于忽略时效。NAV/TTM PE 同日、配对最多相差 3 个美股交易日、完整旧包最多 14 个自然日的规则保留。

## 取数和恢复

1. 完整直接来源包也要再次整包读取，第二次同样验证引用、日期、证券及字段。两次数值/观测日/口径一致才接纳。
2. 如果来源正在更新、第二次无法读取或字段冲突，保留旧的完整合格包；不拼接新旧字段，也不让 DeepSeek 选择一个偏好的值。下次运行若修订后的完整数据连续两次一致，可正常接纳并解释变化。
3. 输入缺失时仍可由 DeepSeek 搜索，但必须回读来源核实；来源完整时零 DeepSeek 调用。双读属于同来源重复一致性检查，不冒充独立供应商交叉验证。
4. 保留原 75 秒估值阶段上限和总运行预算，双读不无限重试。超时走旧包并记录实际使用结果。
5. 缓存统一按数据日、配对日、有效核验时间排序；全相同才固定优先主缓存。不能用文件路径字母顺序或复制后的 mtime 决定哪次修订有效。新来源配对日期倒退不能覆盖同日较新的完整包。
6. 新快照包含版本、完整原始响应、核验时间、输入指纹、每年现金流和结果；读取时重算并核对。损坏或不一致的快照不能挤掉另一份合格缓存。旧版完整来源快照保留兼容重算，不信任旧版保存的加权结果。

## 每次运行证据

`state/qqqm_calculation_audit.json` 保存首次包、复核包、最终选择、此前输入、字段差异和数值变化。常规邮件、指定收件人正式邮件和诊断运行都上传这份记录，保留 30 天；日志也记录实际选用字段和指纹。失败与超时不能标成已核验。

这解决“同输入计算漂移”和“变化没有可追溯依据”的控制缺口，不意味着外部供应商永久无误，或简化模型估值具有客观精确性。真实来源修订、分红更新、配对共识变化仍会改变估值；不会为视觉稳定而隐瞒变化。
