# 昨日动态与关键发言：跨日摘要去重

保留采集器已有的七日标题指纹，新增 `state/published_editorial.json`。
该文件随 daily workflow 的 `state/` 缓存恢复和保存，无需新 API 或额外 LLM 请求。

- 仅记录最终进入邮件、且 SMTP 已成功接受投递后的公司摘要与人物发言。
- 保存最多 30 天、600 条，坏记录跳过；读写失败记录日志，不伪称历史完整。
- 公司生成请求及每位人物的现有请求附加最多 6000 字符的历史数据。
  语义要求是比较核心事件，而不是标题/媒体/发布日期；没有新增事实就省略。
- 输出再用规范化文本的近似匹配作兜底，按公司/人物隔离，避免跨主体误删。
  数字或明确事实状态变化不作自动近似删除，交给语义判断。
- 公司条目删除时同步清理未使用来源；人物先去重，再限流和统一编号。
- 全部重复时沿用无重要动态/无发言的展示方式，不拿旧闻凑数。

边界：旧标题哈希无法反推实际刊发摘要，首次启用没有完整语义历史；不伪造回填。
词汇重写、主体别名及复杂进展仍可能误判，不能承诺绝对零重复。
上下文增加少量输入 token，但不增加请求数；原有运行时间和用量控制继续有效。
