# 参考线末尾空值恢复（2026-09-29）

## 已确认的故障

正式邮件运行 `36502706162`（提交 `b85d5d9`）中，13 个美股/ETF 的日线取数均在有效价格检查失败，随后整只标的的参考线被置为缺失；两个港股成功。原日志没有保存行情原始响应，因此不能证明当时上游空值的发布或缓存原因。

9 月 29 日约北京时间 08:54–08:57 的只读探测复现了相同问题：

- Yahoo 的 2 年日线和 5 年周线窗口包含 9 月 28 日的末尾记录，但 `close=null`；yfinance 同样返回 NaN。
- 改变长窗口长度和 query1/query2 主机没有恢复该记录。它们底层同源。
- 按目标交易日的交易所本地零点到次日零点、`interval=1d` 单独查询，返回有效日 K。例如 MSFT 为 509.2200012207031，NVDA 为 228.86000061035156。
- `tests/fixtures/reference_line_null_tail.json` 保留此次探测的公开 MSFT 日线、最近 200 周及单日响应必要字段；不是原实发时刻的响应。

## 恢复约束

1. 先验证原窗口日期、顺序、连续性和来源身份。仅末尾价格无效时启动单日重取。
2. 单日重取要求唯一记录，日期必须等于交易所最近已收盘交易日；标的、交易所、币种和价格均在该响应中验证。不使用 metadata 的即时价或 fast_info。
3. 替换最新日线 Close，或以同一目标日的 Close 恢复当前周的末尾 Close。此前历史值保持原样，继续使用原有 Close 复权口径与 120/200 周、250 交易日算法。
4. 中间缺行/空值、历史不足、过期或超前记录仍拒绝。恢复失败保留原始故障与重取故障；不缓存，不给数据续期。
5. `stocks.final_bar_invalid` 和 `stocks.final_bar_recovered` 留存周期、目标日期、原 bar 日期和恢复来源；最终行情 source 包含 daily/weekly recovery，进入现有邮件审计归档。

- Python 3.11/3.12 全量离线测试及 Ruff；远端 CI 作为合并门禁。本次不发送真实邮件。

## 剩余边界

单日重取仍是 Yahoo 同源数据，不是独立行情商交叉核验。若该请求也无合格数据，或历史窗口本身损坏，仍保留缺失，不伪造价格。这次验证只确认行情/参考线恢复，不代表估值、新闻及其他板块全部通过审计。
